## 🚮 Удаление файлов (`git rm`)

<details>
<summary>🖱️ Раскрыть команды и примеры</summary>

Команда `git rm` удаляет файлы из рабочей директории и индекса (staging area), подготавливая их к коммиту.

### Основные варианты:

* **`git rm <файл>`**
  Удаляет файл из рабочей директории и индекса.
  *Пример*:

  ```bash
  git rm oldfile.txt
  git commit -m "Удалил oldfile.txt"
  ```

* **`git rm -f <файл>`**
  Принудительно удаляет файл, даже если есть несохранённые изменения.
  *Пример*:

  ```bash
  git rm -f draft.txt  # Удалит, игнорируя изменения
  ```

* **`git rm -r <директория>`**
  Рекурсивно удаляет директорию и все её содержимое.
  *Пример*:

  ```bash
  git rm -r old_folder/
  git commit -m "Удалил папку old_folder"
  ```

* **`git rm --cached <файл>`**
  Удаляет файл только из индекса, оставляя его в рабочей директории. Полезно, чтобы перестать отслеживать файл.
  *Пример*:

  ```bash
  git rm --cached log.txt
  git commit -m "Перестал отслеживать log.txt"
  ```

## 🔄 Переименование файлов (`git mv`)

<details>
<summary>🖱️ Раскрыть команды и примеры</summary>

Команда `git mv` переименовывает или перемещает файлы, автоматически обновляя индекс.

### Основные варианты:

* **`git mv <старое_имя> <новое_имя>`**
  Переименовывает файл и добавляет изменение в индекс.
  *Пример*:

  ```bash
  git mv file1.txt file2.txt
  git commit -m "Переименовал file1.txt в file2.txt"
  ```

* **Ручной способ**:
  Если хочешь переименовать без `git mv`:

  ```bash
  mv file1.txt file2.txt
  git add file2.txt
  git rm --cached file1.txt
  git commit -m "Переименовал file1.txt в file2.txt"
  ```

* **`git checkout -f master`** – принудительно на master, отбрасывает изменения

<details>
<summary>🌿 3.5 Git – Ветки – Перенос веток "вручную"</summary>

Иногда требуется вручную перенести ветку на другой коммит. Это можно сделать несколькими способами.

### 🔄 `git branch -f` – принудительное перемещение ветки

* **`git branch -f <ветка> <коммит>`**
  Перемещает указанную ветку на заданный коммит.
  *Пример:*

  ```bash
  git branch -f main 54a4
  ```

Теперь ветка `main` указывает на коммит `54a4`, но изменения в рабочей директории не затрагиваются.

* **Перемещение ветки на другую ветку:**

  ```bash
  git branch -f main fix
  ```

  Теперь `main` указывает на тот же коммит, что и `fix`.

### 🔄 `git checkout -B` – создание или перемещение ветки

* **`git checkout -B <ветка> <коммит>`**
  Создаёт новую ветку или принудительно перемещает существующую на указанный коммит.
  *Пример:*

  ```bash
  git checkout -B main 54a4
  ```

  Теперь ветка `main` указывает на коммит `54a4`, а изменения в рабочей директории обновлены.

### 🔹 Полный пример переноса вручную:

1️⃣ Создаём новую ветку `fix` и переходим в неё:

```bash
git branch fix
git checkout fix
```

2️⃣ Перемещаем `main` на коммит `54a4`:

```bash
git branch -f main 54a4
```

3️⃣ Или просто перемещаем `main` на `fix`:

```bash
git branch -f main fix
```

4️⃣ Вместо двух команд можно использовать `checkout -B`:

```bash
git checkout -B main 54a4
```

📌 **Важно!** Эти команды **перемещают ветку**, но не изменяют коммиты. Они просто указывают ветку на другой коммит без
создания новых записей в истории.

<summary>🌿 3.6 Git – Восстановление предыдущих версий</summary>

### 🔙 Восстановление файлов из истории

* **`git checkout <коммит> <файл>`**  
  Восстанавливает конкретный файл из указанного коммита.
  ```bash
  git checkout 54a4 index.html

После этого:

  ```bash
  git status  # Покажет, что index.html изменён
  ```

* **Отмена изменений в файле (до последнего коммита)**:
  ```bash
  git checkout HEAD index.html
  ```
  Или сокращённо:
  ```bash
  git checkout -- index.html
  ```

* **Удаление файла из индекса (staging), но сохранение в рабочей директории**:
  ```bash
  git reset index.html
  ```

### 🔄 Полный цикл восстановления:

1. Проверяем историю файла:
   ```bash
   git log -- index.html
   ```
2. Восстанавливаем нужную версию:
   ```bash
   git checkout abc123 index.html
   ```
3. Если передумали - отменяем изменения:
   ```bash
   git checkout HEAD index.html
   ```
4. Если уже добавили в индекс - сбрасываем:
   ```bash
   git reset index.html
   ```

📌 **Важно:**

- `git checkout <коммит> <файл>` перезаписывает файл в рабочей директории
- Изменения нужно закоммитить после восстановления
- Без указания коммита (`HEAD`) - откатывает до последнего коммита

</details>

<summary>🌿 3.8 Git – Ветки – Просмотр истории и старых файлов</summary>

### 🔍 Специальные символы для навигации по истории

#### Основные указатели:

* **`HEAD`** или **`@`** - текущий коммит
* **`HEAD~2`** - 2 коммита назад от HEAD (по первой родительской ветке)
* **`HEAD^`** или **`HEAD~1`** - предыдущий коммит
* **`HEAD^^`** - 2 коммита назад (эквивалентно `HEAD~2`)
* **`HEAD^2`** - второй родитель (для merge-коммитов)

#### Примеры:

```bash
git show HEAD~3        # Покажет коммит 3 шага назад
git diff HEAD^ HEAD    # Сравнит текущий и предыдущий коммит
```

### 📜 Просмотр старых версий файлов

```bash
git show HEAD~2:README.md      # Покажет README.md 2 коммита назад
git checkout 54a4 -- file.txt  # Восстановит file.txt из коммита 54a4
```

### 🔎 Поиск в истории

* **По сообщению коммита**:
  ```bash
  git log --grep="исправление"
  ```

* **По изменениям в файле**:
  ```bash
  git log -p -- index.html
  ```

* **По автору**:
  ```bash
  git log --author="Иван"
  ```

* **По диапазону коммитов**:
  ```bash
  git log HEAD~5..HEAD
  ```

### 🕵️ Поиск строки в истории (git grep)

```bash
git grep "функция" HEAD~10     # Ищет "функция" в коммите HEAD~10
git grep -n "TODO" -- '*.js'   # Ищет TODO во всех .js файлах
```

### 🌟 Полезные комбинации:

```bash
# Показать историю с графом ветвления
git log --oneline --graph --all

# Найти коммит, где добавили строку
git log -S "some_code" -p

# Показать изменения конкретного файла за последние 3 дня
git log --since="3 days ago" -p -- index.html
```

📌 **Совет:** Используйте `:` для доступа к файлам в старых коммитах и `⧸` для поиска по шаблону.
